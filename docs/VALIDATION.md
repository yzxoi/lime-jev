# 0.1.0 验证记录

日期：2026-09-23。机器：Apple M3 Max、64 GiB 内存、macOS 26.6.2。Qwen3-0.6B IQ4_XS 使用 Metal；Laya multilingual 使用 MLX float16。模型版本与校验和见 [模型清单](../scripts/models.json)。

## 为什么默认不启用 Laya

本项目没有把“接入另一个模型”等同于“输入会更准”。lime 原有 `single_ci` 路径倾向于已有单 token 词；“油箱”“又想”有时需要组合多个 token，原来甚至不在前 8 个候选里。只做重排无法修复这种召回缺失。

本版对不超过 4 个音节的输入增加有界词组搜索，比较完整路径概率，最多扩展 4 个分支、每分支取 3 个后续匹配，并缓存逐键共享的推理结果。同时修正 `yo`、`qio` 等未完成拼音的切分。模型、词汇表和上下文不需要换成大型模型。

Laya 后端已实际接通，但当前提示方式下会作出明显错误的选择，因此默认关闭，页面可切换到实验模式。没有根据这 32 个样例训练模型，也没有为“汽车”“我现在”写死词语规则。

## 小样本开发诊断

[32 个合成用例](../benchmarks/cases.json)由开发时人工编写，包含同音词和歧义词；不是盲测集，也不是日常输入准确率。`我现在` 本身有歧义，本诊断将“又想”作为需求示例的目标。词组搜索方案在这些样例上开发过，存在选择偏差，需要更多真实文本验证。

| 路径 | 目标首选 | 目标在前 8 个候选 | 延迟 P50 / P95 |
| --- | --- | --- | --- |
| lime 原有 `single_ci` 路径 | 26 / 32 | 26 / 32 | 96.8 / 181.4 ms |
| 本版语境词组路径 | 30 / 32 | 31 / 32 | 103.5 / 277.9 ms |
| Laya 独立选择诊断 | 22 / 32 | 人工预先提供目标 | 8.1 / 11.4 ms |

前两行使用相同 Qwen 权重，每例替换上下文后调用引擎，包含上下文处理，不含模型启动、HTTP 或 Rime。第一行是同一衍生代码中的原有生成路径，不能代表全部上游功能。

Laya 行使用人工提供的 2–3 个同音候选，只计 `predict` 耗时，输入条件与前两行不同，**不能作为三种端到端系统的公平排行榜**。倒置候选顺序后，只有 23 / 32 例保持选择不变。最初诊断调用耗时 147.5 ms，P95 按 nearest-rank 计算。真实 8 候选 API 测试中，Laya 还曾把“汽车”后的“油箱”换成“优享”；这也是默认关闭它的原因。

原始合成数据与逐例输出：[原路径](results/lime-baseline.json)、[词组路径](results/lime-evaluation.json)、[Laya](results/laya-evaluation.json)。这些文件只含本仓库的合成输入，没有个人输入历史。

## 逐键与端到端验证

[逐键结果](results/typing-smoke.json)覆盖“汽车”“我现在”“请把附件发到我的”，并重复替换一次上下文。四次最终输入 `youxiang` 的首选均正确；最后一键耗时为 **3.8–17.7 ms**，中途某些键仍需 **约 90–170 ms**。这些是引擎时间，不能宣称每个按键都低于 20 ms。一次性粘贴整个拼音、冷缓存、较慢机器会有更长等待。

本机已验证：

- `./lime-jev install` 完整执行：依赖安装、全部模型 SHA-256 校验、Swift 辅助程序编译、Rime 部署、launchd 启动与本地页面打开；再次 `stop` / `start` 成功。
- 19 个 Deno 测试通过，含上游全拼/双拼解析回归，以及会话隔离、过期、并发、重排边界、服务失败、应用切换中丢弃旧结果。
- 2 个 Python 安装测试通过：重复安装、精确恢复原文件、保留用户后续修改。类型检查、lint、格式检查、Python 编译与 shell 语法检查通过。
- 本地 HTTP：访问密钥、Origin 限制、非法拼音拒绝、前缀提交、清空、三组候选、Laya 实际推理及缓存通过。
- 停止 Laya 服务后仍返回 lime 候选；100 ms 选择预算到期也保留候选。新形状的第一次 MLX 请求可能触发此回退。
- 使用鼠须管自带 `librime` 1.16 与 `librime-lua`，在独立临时配置中逐键执行：`qiche` → 提交“汽车” → `youxiang` 首选“油箱”；清空语境后 `wo` → 提交“我” → `xianzai` → 提交“现在” → `youxiang` 首选“又想”。这条链路使用发布的 schema、Lua、curl、本地 HTTP 服务和实际模型，未模拟候选。
- 停止全部服务后，同一 Rime 引擎仍可从内置词典给出候选。
- 控制页浏览器实测“汽车”和“我现在”候选变化，检查窄窗口布局。

系统设置中已存在鼠须管输入源，但本次 GUI 自动化未能触发 TextEdit 的系统候选窗口。因此上述 Rime 验证是实际输入引擎 API 测试，**不等于已覆盖每个 macOS 应用的 GUI 输入体验**。实际使用时从输入菜单选择鼠须管，再按 Control + ` 选择“Lime · 本地语境”。

原生引擎诊断代码见 [rime_smoke.cc](../benchmarks/rime_smoke.cc)。它只使用临时配置，不操作已有用户词典；复现说明见 [Rime 测试](RIME_TEST.md)。

## 当前边界

- 仍有错误：“处理 gongshi”未召回目标“公事”；“耐用的 gangkou”召回“钢扣”但仍把“港口”排前。罕见词、人名、专业词和长句尚需更多验证。
- 默认简体输出；回退词典通过 Rime 的简体转换。模型也可能产生不自然词组，需用户确认。
- 模型只知道本输入方案提交的前文和当前预编辑文字，不会读取应用的完整文档；粘贴进编辑器的文字不自动进入语境。
- 切换应用、常见编辑键、中英文模式变化、60 秒空闲会清空语境。同一应用内鼠标切换输入框或外部编辑无法可靠检测，需 Control + Shift + Backspace。
- 第一版支持 Apple Silicon + 鼠须管全拼。本机只验证 macOS 26.6.2；macOS 14+ 是依赖要求，并非已逐版测试。
- Laya 分数不是经过输入法数据校准的正确率。网页显示“模型分数”，仅供比较。
- 首次安装需要下载依赖和模型；服务推理在回环地址上运行，不调用 Jev 或其他云端推理 API。其他本机进程与当前用户有相同权限时，不构成独立安全边界。
